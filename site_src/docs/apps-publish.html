Test and publish an app

From an empty folder to a merged app. The format itself is in the Apps API.

1. Set up

git clone https://github.com/Kalmai221/PythonOS
cd PythonOS
python -m pip install -r requirements.txt

You need Python 3.9 or newer. Make a branch for your app: git switch -c app-hello.

2. Write it

Create online_packages/<category>/<name>/ with a data.json and a run script. Copy a small existing app as a start: online_packages/games/flood (no permissions), online_packages/utilities/todo (stores data), online_packages/utilities/pomodoro (a timer). Rules that keep apps consistent:

  • Use only the standard library and the libraries PythonOS already ships (rich, requests, psutil), unless you really need another. A new library means API 2 and an app that cannot run on the live USB.
  • Draw with plain ASCII where you can. Not every terminal and font has box and block characters.
  • Put the logic in functions so it can be tested, and keep execute(args) thin.
  • Ask for the fewest permissions that work, and handle PermissionError with a clear message.
  • Handle Ctrl+C and end of input (KeyboardInterrupt, EOFError) without a traceback.

3. Run it

The quickest way is to run the script directly. Apps import pyos with a fallback, so they work outside PythonOS:

python online_packages/games/hello/run.py Ada

To try it the way a user would, with the permission guard on, start PythonOS from the repository (python main.py), and install the folder: copy it to files/installed_<category>/<name>/ and type reload. Then hello Ada runs it through the sandbox.

4. Check it

python tools/build_index.py          validates data.json and rebuilds the catalog
python tools/audit_lockdown.py       if the app is lockdown_safe
python tools/check_docs.py           every app needs a description and its exports
python tools/smoke_test.py           everything, including the app tests

build_index.py rewrites online_packages/index.json, index-api1.json and index-api2.json. Commit those with your app: the checks fail if they are out of date.

Write a test for the logic. The other apps' tests are in tools/test_newapps.py, tools/test_assistant.py and tools/test_marketplace_pip.py: a file named tools/test_*.py is run by the smoke test automatically. A good test loads run.py by path, calls the pure functions, and asserts the results.

5. Open the pull request

  • One app (or one change to an app) per pull request.
  • If you changed an existing app, raise its version and add a line to its changelog. Without that, users do not get the update.
  • Add a line under ### PythonOS in the Unreleased or newest section of CHANGELOG.md.
  • Say in the description what the app does, what it asks for and why, and which systems you tried it on. A screenshot or pasted terminal output helps.

GitHub runs the checks on your pull request (what they are). A maintainer reviews the code, the permissions it asks for, and whether it should be lockdown_safe. More in Pull requests.

After it is merged

PythonOS reads the catalog from the main branch, so the app appears in the store, and in the App Library, as soon as the pull request is merged. There is no separate upload. Apps do not wait for a PythonOS release.
