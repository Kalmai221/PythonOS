When something goes wrong

PythonOS has a few tools for the case where it will not start, will not log in, or keeps stopping. None of them needs a password, and none of them gives a way out to the system underneath.

The boot menu

On the bootable USB and the virtual machines, press M while the start-up message is on screen. On any other export, start PythonOS with --menu.

1Start normally
2Safe mode
3Diagnostic start: verbose, and saves a hardware report
4Emergency console
5, 6Restart, power off

Pressing D at the same moment goes straight to the diagnostic start.

Safe mode

Safe mode starts only the system itself. Apps from the marketplace, the startup commands of each user and the background checks are left out, and the long animations are skipped. Use it when something you added stops PythonOS from starting.

python3 main.py --safe       start once in safe mode
safe on                      (in the emergency console) safe mode at every start until you say safe off

The emergency console

A small, read-only console that needs no login. Open it from the boot menu, with --emergency, or let it open by itself: after repeated crashes in a short time PythonOS offers it, and on the bootable USB the start-up script opens it after three stops in two minutes.

It can read the system log, the crash reports, the boot log and a hardware report, and pack them into one zip for you to send. It cannot run programs and cannot read your files, accounts or saved passwords.

statusWhat happened last time, and the state of the system
logs [n]The last n lines of the system log
crashes, crash <n>List the crash reports, show one
bootlogHow the last starts went, step by step
diagA hardware and driver report
savelogsPack the logs and the report into a zip. If a USB stick is plugged in it offers to copy it there.
safe on|offSafe mode for the next start
resetClear the crash counter
restart, shutdownDo what they say

Crash reports

When PythonOS crashes it writes the full trace to a crash report, and also writes a ready-to-send problem report with names, home folders, email and IP addresses removed. Nothing is sent. After you log in:

whathappened             what the last session was doing when it stopped
report --pending         read the waiting report, then send it or save it as a file
report                   write a report about something else
report status            what became of a report you sent: its state and any replies

You always see the whole text before anything leaves your computer, and writing it works without a network. You choose how to send it:

  • GitHub - the issue is created under your own GitHub account with the gh command, the real GitHub CLI. The ISO and virtual machines include it; everywhere else PythonOS asks before downloading it into its own folder (nothing is installed on the computer). PythonOS has no browser, so gh shows a one-time code and you approve it on another device (your phone or another computer); PythonOS then carries on by itself. The sign-in is deleted afterwards unless you choose to stay signed in. On Android there is no gh, so use Discord or a file.
  • Discord - no account needed. The report goes to the developer's channel. It is not a GitHub issue, so there is no number to follow.
  • A file - saved in your home folder, with the short address of the GitHub issues page to paste it into from another device.

Other tools

  • doctor checks the installation (disk, files, accounts, packages) and offers fixes.
  • logs, logs --crashes and bootlog show what PythonOS wrote down.
  • rollback goes back to the version before the last update.
  • diag makes a hardware report you can attach to an issue.
