Getting started

Install or boot PythonOS (see Download), then follow this page once. It takes ten minutes.

The first start

The first time PythonOS starts it walks you through a short setup: your account and password, a few preferences, a check for updates, and a choice of starter apps. On the bootable USB and the virtual machine images it also looks at your hardware (keyboard layout, time zone, network) first.

PythonOS keeps its own memory budget. It is 1 GB by default; you choose it during setup, or later with settings. On the live USB it uses the whole machine.

On the bootable USB and the virtual machine the system forgets everything when it is switched off unless a data disk is attached. The .ova already has one. See where your data lives.

Finding your way

help                     the groups of commands, numbered, and an "I want to..." table
help 3                   open group 3
help copy a file         ask in your own words
help cp                  one command: usage, examples, related commands
man cp                   the full manual page
tutorial                 a guided tour that checks what you type

At the prompt, Tab completes a command or a file name and shows a menu when there is more than one match. Ctrl+R searches your history as you type, the up arrow steps back through it, and a grey suggestion from your history can be accepted with the right arrow. Commands are coloured: green when they exist, red when nothing could match. history lists what you typed (history git searches it), and !! repeats the last command. Do not like it? settings set fancy_prompt off gives the plain prompt, and settings set prompt_keys vi uses vi keys.

Files and folders

pwd                      where am I
ls -l                    what is here, with sizes and dates
cd ~/documents           go somewhere (~ is your home folder)
mkdir notes              make a folder
edit notes/todo.txt      the built-in editor
cat notes/todo.txt       show a file
cp a.txt b.txt           copy
mv b.txt notes/          move or rename
rm a.txt                 remove: it goes to the trash
undo                     bring the last removed file back
find -name "*.md"        find files by name
grep -n error log.txt    find text in a file
fm                       a full-screen file manager

The shell

PythonOS has the parts of a shell you would expect.

ls | grep txt            pipe the output of one command into another
echo hi > a.txt          write to a file (>> adds to it)
make && echo ok          run the second only if the first worked
sleep 30 &               run in the background (jobs lists them, fg 1 brings one back)
NAME=Ada                 a variable; use it as $NAME
alias ll="ls -l"         a short name for a command (kept for you)

Put aliases and variables in ~/.pyosrc and they are set at every login. Long output of listing commands is shown a screen at a time; the settings auto_page and clear_style change that.

Apps

market                   browse the store
pkg install chess        install an app
run chess                start it (an app's own command works too: chess)
pkg update all           update every installed app
pkg permissions chess    see and change what an app may do
settings app chess       the options an app offers

Before an app is installed, PythonOS shows what it may do: connect to the internet, read your files, show notifications, and so on. It is held to that while it runs. The App Library shows the same for every app.

Settings, accounts and updates

settings                 every setting, in one full-screen program
passwd                   change your password
manageusers              add and remove accounts (administrators)
backup create            back up your files
updatecheck              look for a newer PythonOS and install it
whatsnew                 what the last update changed
version                  which version this is

Useful to know

  • taskman (or ps) shows what is running inside PythonOS. kill <id> stops a task.
  • timesync sets the clock from the internet. A wrong clock breaks secure connections.
  • doctor checks the installation and offers to fix problems.
  • shutdown and restart do what they say, with a proper shutdown screen.

If something goes wrong, read When something goes wrong.
