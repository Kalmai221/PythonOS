Where it runs

PythonOS is packaged in several ways. These are called exports. The system inside is the same; the package around it is not.

Two kinds of update

PythonOS is made of two layers, and they update differently.

  • The core is PythonOS itself: the shell, the commands, the apps' runtime. updatecheck downloads a new core and swaps it in, on every export.
  • The package is what is around the core: the Windows launcher and Python, the Android app, the kernel and boot setup of the ISO, the Docker image. A new package is needed only when a release changes it. PythonOS says so and shows where to get it, and offers to install it itself where the system allows.

Release notes follow the same split. Each release lists PythonOS updates (what updatecheck brings) separately from export updates (what needs a new download).

The exports

ExportWhat it isYour data
WindowsAn installer (and a portable zip) with its own Python and a terminal window. Windows 10 1809 or newer, Intel/AMD or ARM.In the install folder, kept across updates.
AndroidAn app with a built-in terminal. A 1 MB installer app picks the right one for your processor. Android 7 or newer.The app's private storage.
Linux.deb, .rpm, Arch package or tarball. Any processor; needs Python 3.9 or newer.The install folder.
Bootable USBAn ISO for a PC (x86_64) or an ARM computer with UEFI. A complete system that starts from the stick and leaves the disk alone.Forgotten at power off unless a data disk is attached.
Virtual machineThe same system as the ISO, as an .ova (VirtualBox, VMware) or .qcow2 (QEMU, KVM, Proxmox).The .ova has a data disk. For the .qcow2 attach the data disk image.
DockerA container image for amd64 and arm64.A volume mounted at /data.

There is no macOS build. On a Mac, use Docker or a virtual machine.

Data disks on the USB and virtual machines

The live system runs from memory, so nothing is saved by default. A disk or partition labelled PYOS_DATA changes that: PythonOS finds it at start and keeps your accounts, files and settings there. Updates are kept there too, so an update made with updatecheck is still there after the next start.

persist status           is a data disk in use?
persist create           make one from a spare disk (add --encrypt to encrypt it)

Without a data disk, updatecheck warns you that the update would be gone after a restart. For a lasting system, installos installs PythonOS on a disk of the computer. It erases that disk, so it asks you to type the disk's name first.

What the live USB does not do

The live system is locked down: there is no login on the Linux underneath, no shell, and nothing PythonOS runs can start your own programs. Because of that, apps that need to start programs or install Python libraries do not run there. The App Library shows which apps run on the live USB.

Commands that depend on the export

A few commands exist only where they make sense. installos, persist, hwsetup and display are for the bootable USB and the virtual machines. Typing one elsewhere tells you where it works.
