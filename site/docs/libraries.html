Libraries

PythonOS needs very little to start. Everything else is optional: when a library is installed PythonOS uses it, and when it is not, the feature still works in a simpler way or says plainly what is missing.

Required

These are in requirements.txt. PythonOS does not start without them, so the list is kept short: changing it makes Android and the bootable USB need a new package.

LibraryUsed for
richAll the output: tables, panels, colours, progress.
prompt_toolkitThe prompt (history search, suggestions, completion menu, coloured commands), the editor, the file manager and the settings app.
psutilProcesses, memory, disks and network information.
requestsWeb requests: updates, the marketplace, curl, wget, web.
pygmentsSyntax colours in cat.
yaspinThe spinner on the boot and shutdown screens.
tzdataTime zones on systems that have none of their own.

Optional

These are in requirements-extra.txt. You choose which to have. The Windows installers (the web installer and the full one) show a list with everything ticked, the first-time setup asks on every other system (on the bootable USB and in virtual machines the choice is download-on-demand, so it needs the internet), and the extras command changes the choice any time: extras lists them, extras choose picks from a list, extras install py7zr adds one. Your choice is kept, and an update installs what you chose (everything, if you chose all) and only tells you about new ones if you picked by hand. The Android app carries the libraries that have an Android build inside (all but py7zr and watchfiles, which need compiled parts), so there the first start asks which to switch on, and extras switches them on and off; nothing is downloaded.

Code asks for an optional library through pyos.optional (optional.get("yaml") returns the module or None). Write the fallback first, then the improvement. tools/test_libs.py tests every one of these features both with the library and without it.

Libraries for apps

An app that needs a library of its own lists it in data.json (marketplace API 2, see the Apps API). The marketplace installs it for that app only. Two apps do this today: Units (pint: thousands of units) and Image Viewer (Pillow and rich-pixels: pictures in the terminal). Apps with libraries do not run on the live USB.

For tests only

Listed in requirements-dev.txt. PythonOS never needs them.

hypothesisProperty tests (tools/test_properties.py): random input to the DNS reader, the date parser, the pager, cut, seq, tr and more, checking they never crash and keep their promises. It found real bugs in the DNS reader.
pint, Pillow, rich-pixelsSo the two library apps can be tested.
flake8, pylint, ruff, bandit, verminThe static checks in CI.

Adding a library

  1. Ask whether it must be required. Almost always the answer is no: make it optional, with a fallback.
  2. For an optional library: add it to requirements-extra.txt with a comment saying what it adds, add the Alpine package to the ISO list in OS_Export/ISO/mkimg.pythonos.sh if one exists (CI checks the name), and add it to the Android list only if it is pure Python.
  3. Use it through pyos.optional, write the fallback, and add a check to tools/test_libs.py that runs both ways.
