Tests and CI

Every pull request runs the same checks you can run on your own computer. Run them first and CI will be green.

The checks, one by one

CommandWhat it checks
python tools/smoke_test.pyCopies PythonOS to a scratch folder, signs in, and runs about ninety real commands (pipes, redirects, files, trash, aliases, network usage messages and more), then the login path, the update strategies, services, limits, the settings app and every tools/test_*.py file. This is the main test.
python tools/audit_lockdown.pyFails on any code that can start a process or evaluate code and is not on the reviewed list. It also holds apps marked lockdown_safe to the same rules. This protects the live USB.
python tools/build_index.pyValidates every app's data.json and rebuilds the catalog files.
python tools/check_docs.pyEvery command has a manual page and a help group, every manual page belongs to a command or topic, every app has a description and its exports.
python tools/build_site.py --checkThe website in site/ is what site_src/ produces.
python tools/check_site.pyEvery link, script and style the pages point at exists, every page has a title, and the JavaScript parses.
python OS_Export/ISO/check_packages.pyEvery Alpine package the ISO asks for exists (needs a network).

The tools/test_*.py files each cover one area: test_newapps.py (the app logic), test_netcmds.py (DNS packets, argument parsing, no network), test_recovery.py (emergency console, safe mode, boot menu), test_changelog.py, test_marketplace_pip.py, test_assistant.py. Run one alone: python tools/test_netcmds.py.

Writing a test

For a command, add a line to CHECKS in tools/smoke_test.py: ("seq 3 | tac", "3\n2\n1", 0) is the command, text its output must contain, and the exit status. For logic, add a file tools/test_something.py with a main() that asserts and prints one line when it passes. Tests must not need a network unless they say so, and must not touch your real data: the smoke test runs in a scratch copy, and new tests should use a temporary folder.

Some checks need the repository itself and are skipped when the smoke test runs inside a package or a container image (HAVE_REPO is false there).

What GitHub runs

The Test workflow runs on every push to main and every pull request, in four groups:

JobWhat it does
Test (Linux, Windows, macOS)The lockdown audit and the smoke test on each system.
Python 3.9, Python 3.14The smoke test on the oldest Python we support and the newest.
Static checksNo syntax errors or undefined names (flake8); nothing needs a Python newer than 3.9 (vermin); pylint (errors only); ruff (the rules the code already follows); all three catalog files current; manual and help groups complete; the website current and its links valid; shell scripts parse; ISO package names exist in Alpine. Bandit and the full ruff report run too, for information only.
Windows installer and hostThe C# installer compiles and the PowerShell scripts parse.

Other workflows: Build PythonOS builds every package and, for a version tag, publishes the release (see releases); Website publishes site/ to GitHub Pages; Security checks runs weekly (known vulnerabilities in the dependencies, and the lockdown audit). The live build status page shows the latest runs.

When a check is red

  • Open the failed step, not just the job. The last lines name the check and what it found.
  • Red on one system only is real: PythonOS runs on all of them. (The macOS run once caught a command that crashed on Apple silicon.)
  • The catalog and website checks fail when a generated file is stale. Run python tools/build_index.py or python tools/build_site.py and commit the result.
  • pylint reports errors only, with a few message types turned off because they are false alarms (the reasons are in .pylintrc). If you think it is wrong about your code, say so in the pull request.
